# 实时信号虚拟成交与前向模拟账本设计规格

日期：2026-08-06  
状态：已批准，待实施计划

## 1. 目标

收件箱中的买入、补仓和卖出消息不能只是建议。对于由实时回测监控器产生的策略成交消息，系统必须先在独立的虚拟账本中完成成交，再生成收件箱消息，从而保证：

- 收到“虚拟已买入”消息，代表系统已经按信号触发时的实时价格虚拟买入。
- 收到“虚拟已补仓”消息，代表虚拟持仓已经增加。
- 收到“虚拟已卖出”消息，代表虚拟账本已经完成相应数量的卖出。
- 所有虚拟成交均能进入前向模拟记录，并形成持仓、盈亏、胜率和收益率。
- 用户点击消息中的实际交易按钮时，才修改实际持仓账本。

本功能属于实时前向验证，不将其实时结果混入历史 K 线回测结果。

## 2. 范围

### 2.1 本期包含

- 新建回测虚拟持仓与交易账本。
- 将信号去重状态、收件箱消息和虚拟账本统一保存。
- 买入、补仓、部分卖出、全部卖出和 T+1 限制。
- 收件箱展示虚拟成交信息。
- 新增前向模拟持仓、成交记录、完整交易周期和统计指标。
- 将旧 V2 收件箱迁移为未纳入虚拟交易的历史消息。
- 保持实际持仓账本和虚拟账本相互独立。

### 2.2 本期不包含

- 不根据旧收件箱消息倒推虚拟交易。
- 不根据现有实际持仓反向构造虚拟持仓。
- 不将前向模拟成绩合并进历史回测指标。
- 不改变历史回测引擎的策略和指标计算方法。
- 不自动替用户执行实际证券交易。

## 3. 核心概念

系统同时保留三套独立记录：

1. 历史回测：利用历史 K 线计算的策略表现。
2. 前向模拟：实时信号触发后由系统执行的虚拟交易。
3. 实际持仓：用户确认后记录的真实持仓和交易。

三套记录不得混算收益、胜率、持仓或交易次数。

## 4. 总体架构

### 4.1 数据流

```text
自选股与实际持仓监控范围
        ↓
实时行情进入回测监控器
        ↓
策略信号发生 hold → buy/sell 的边沿变化
        ↓
信号成交运行时校验价格、去重、持仓与 T+1
        ↓
先在内存中完成虚拟成交
        ↓
生成引用同一虚拟交易的收件箱消息
        ↓
通过一次存储写入保存运行状态
        ↓
用户可选择是否操作实际持仓
```

### 4.2 模块边界

- 实时回测监控器：只负责计算行情快照对应的买卖决策，不直接写收件箱或账本。
- 信号成交运行时：负责信号边沿识别、虚拟成交、T+1、去重和统一持久化。
- 虚拟账本领域模块：负责持仓、成本、交易、已实现盈亏和交易周期计算。
- 收件箱：展示成交结果、受限提醒和实际操作入口。
- 实际持仓账本：继续管理用户确认的实际交易，不被虚拟成交自动修改。

## 5. 统一运行状态

现有收件箱 V2 升级为统一的 V3 运行状态。推荐存储键：

```text
sec_bt_signal_runtime_v3
```

V3 状态至少包含：

```ts
interface BacktestSignalRuntimeState {
  version: 3;
  alerts: BacktestSignalAlertV3[];
  stocks: Record<string, StockSignalStateV3>;
  virtualLedger: VirtualTradingLedger;
}
```

收件箱、信号去重状态和虚拟账本必须通过一次 `setItem` 保存，避免出现有消息无成交或有成交无消息。

## 6. 虚拟账本

### 6.1 虚拟持仓

每个虚拟持仓至少包含：

- 股票代码与名称。
- 策略标识和策略版本。
- 总持仓股数。
- 可用股数。
- 平均成本和剩余总成本。
- 首次建仓时间和最近更新时间。
- 关联的虚拟交易编号。
- 当前交易周期编号。

持仓身份按“股票代码＋策略标识”区分，防止将未来不同策略的持仓错误合并。

### 6.2 虚拟交易

每笔虚拟交易至少包含：

- 唯一 `virtualTradeId`。
- 唯一 `sourceSignalId`。
- 交易周期编号。
- 股票代码、名称、策略标识和策略版本。
- `buy` 或 `sell`。
- `open`、`add`、`reduce` 或 `exit`意图。
- 成交股数、成交价格、成交金额和成交时间。
- 成交后的总持仓与可用持仓。
- 卖出交易的已实现盈亏。
- 信号原因和指标快照。

### 6.3 完整交易周期

完整周期从首次虚拟买入开始，在该策略下该股票的虚拟持仓清零时结束。周期保存：

- 首次买入和最终卖出时间。
- 累计买入金额和累计卖出金额。
- 累计已实现盈亏和周期收益率。
- 持有时间。
- 买入、补仓和卖出交易编号。
- 已结束或仍持有状态。

## 7. 成交规则

### 7.1 买入与补仓

- 无虚拟持仓时出现新的买入边沿，按信号实时价格买入100股，意图为 `open`。
- 已有虚拟持仓时出现独立的补仓边沿，按信号实时价格再买入100股，意图为 `add`。
- 新买入股数立即计入总持仓，但当日不计入可用持仓。
- 补仓后按总成本除以总股数重新计算平均成本。

### 7.2 卖出

- 卖出数量使用现有信号推荐数量。
- 卖出数量不得超过虚拟可用持仓，并向下约束为100股的整数倍。
- 卖出部分持仓时意图为 `reduce`。
- 卖出后持仓清零时意图为 `exit`，同时结束当前交易周期。
- 已实现盈亏按虚拟持仓平均成本计算。

### 7.3 成交价格

- 使用信号触发时实时行情中的价格。
- 不使用用户打开消息时的价格。
- 价格必须有限且大于零。
- 无效、缺失或过期价格不得生成虚拟成交和“已成交”消息。

### 7.4 T+1

- 当日虚拟买入的股票在下一交易日才转为可用。
- 当卖出信号超过可用股数时，只执行可用部分。
- 可用股数不足100股时，不执行卖出。
- 如果卖出完全受 T+1 阻断，生成一次“卖出受限”提醒并记录最早可卖交易日。
- 下一交易日卖出条件仍成立时，使用新的实时价格正式成交并生成虚拟卖出消息。
- 受限提醒不作为回测卖出交易，也不结束交易周期。

## 8. 信号去重与幂等

- 买入方向从 `hold` 变为 `buy` 时只成交一次。
- 条件持续为 `buy` 时不得因刷新、轮询或重启重复成交。
- 信号恢复为 `hold` 后再次变为 `buy`，才能产生新的买入或补仓。
- 卖出方向使用同样的边沿规则。
- 每个成交信号必须有稳定的 `sourceSignalId`。
- 虚拟账本不得出现重复的 `sourceSignalId`。
- T+1受限状态需要单独保存，避免同日重复发出受限提醒，同时允许下一交易日再次尝试。

## 9. 收件箱消息

### 9.1 虚拟成交消息

新成交消息必须包含：

- 虚拟已买入、已补仓、已部分卖出或已全部卖出的明确标识。
- 成交价格、成交股数、成交时间。
- 成交后的总持仓与可用持仓。
- 策略名称和策略版本。
- `sourceSignalId`、`virtualTradeId`和交易周期编号。
- 信号原因和指标快照。
- 用户操作实际持仓的按钮。

虚拟成交消息的实际操作状态继续使用 `pending`、`bought`和`sold`，但该状态只表示用户是否同步操作了实际持仓，不表示虚拟成交状态。

### 9.2 实际持仓风控提醒

如果一只股票只存在于实际持仓中，虚拟账本从未建仓，系统仍可发送实际持仓补仓或卖出风险提醒，但必须：

- 明确标记为“实际持仓风控提醒”。
- 不生成虚拟卖出交易。
- 不纳入前向模拟收益和胜率。
- 不伪造成本、收益或完整交易周期。

### 9.3 历史消息

V2消息迁移后标记为“历史信号，未纳入虚拟交易”，不显示虚拟成交编号，不进入前向模拟统计。

## 10. 前向模拟记录界面

新增独立的“前向模拟记录”区域，包含：

### 10.1 当前虚拟持仓

- 股票、策略和策略版本。
- 总持仓与可用持仓。
- 平均成本、实时价格。
- 未实现盈亏和收益率。
- 首次建仓时间和持有时间。

### 10.2 成交明细

- 买入、补仓、部分卖出和全部卖出流水。
- 成交价格、股数、金额、时间和信号原因。
- 可跳转到对应收件箱消息和个股分析页面。

### 10.3 完整交易周期

- 累计投入、累计卖出和净收益。
- 周期收益率和持有时间。
- 周期内所有关联交易。

### 10.4 统计指标

- 胜率只统计已经完全清仓的交易周期。
- 部分卖出立即产生已实现盈亏，但持仓未清零前不增加胜负次数。
- 未平仓持仓只计入浮动盈亏，不计入胜率。
- 展示累计已实现盈亏、未实现盈亏、总盈亏、已结束周期数和当前持仓数。
- 历史回测、前向模拟和实际持仓分别展示，不允许合并统计。

## 11. 实际持仓操作

- 用户点击虚拟买入消息中的买入按钮后，继续填写实际股数和持仓组。
- 实际成交价格默认使用当前实时价格，不强制使用虚拟成交价格。
- 实际持仓交易继续写入现有实际持仓账本。
- 实际交易引用收件箱消息编号，但不得修改虚拟持仓或虚拟交易。
- 用户不点击实际交易按钮时，虚拟账本仍正常运行。

## 12. 持久化与错误处理

### 12.1 单次提交

每次处理新信号时：

1. 加载并校验 V3 状态。
2. 在内存副本中识别边沿和计算虚拟成交。
3. 创建引用虚拟交易的收件箱消息。
4. 更新信号状态。
5. 通过一次存储写入提交整个 V3 状态。

如果写入失败，步骤2至4均不得在页面内被视为成功，下一次行情更新可以重试。

### 12.2 数据损坏

- V3数据结构必须进行版本和必要字段校验。
- 数据损坏时不得静默重置虚拟账本。
- 系统停止生成虚拟成交消息，并在收件箱顶部显示可操作的错误。
- 实际持仓账本不能被连带清空或重建。

### 12.3 存储容量

- 收件箱展示列表可以按现有规则裁剪旧消息。
- 虚拟交易和已结束周期不得随着消息裁剪而删除。
- 后续可提供显式导出和清理功能，本期不自动删除交易历史。

## 13. V2迁移

- 首次加载时读取V2收件箱。
- 将消息内容、已读状态和实际操作状态迁移到V3。
- 旧消息的虚拟成交状态固定为 `legacy_untracked`。
- V2信号状态不用于构造虚拟持仓。
- V3虚拟账本从空账户开始。
- V2存储键在V3成功保存前不得删除。
- 实际持仓账本不参与此次迁移。

## 14. 验收测试

至少覆盖以下场景：

1. 新买入边沿同时产生100股虚拟买入和关联消息。
2. 虚拟成交价格等于触发时实时价格。
3. 持续买入条件不会重复成交。
4. 信号恢复后重新触发可以补仓100股。
5. 补仓正确更新平均成本。
6. 部分卖出正确更新剩余成本和已实现盈亏。
7. 全部卖出结束交易周期并进入胜率统计。
8. 未平仓周期不进入胜率统计。
9. 当日买入后卖出信号被T+1阻断。
10. 同一交易日不会重复生成T+1受限提醒。
11. 下一交易日信号仍成立时按新价格成交。
12. 卖出数量不超过可用持仓且为100股整数倍。
13. 无效实时价格不生成交易或已成交消息。
14. 重复 `sourceSignalId` 不会产生重复交易。
15. 页面刷新和程序重启不会重复成交。
16. 存储失败时交易、消息和信号状态均不提交。
17. V2消息迁移后标记为历史未跟踪消息。
18. V2消息不进入前向模拟统计。
19. 实际持仓风控提醒不生成虚拟卖出交易。
20. 用户操作实际持仓不改变虚拟账本。
21. 收件箱裁剪不会删除虚拟交易和周期记录。
22. 历史回测、前向模拟和实际持仓指标保持隔离。

## 15. 成功标准

- 任意标记为虚拟已成交的收件箱消息都能找到唯一虚拟交易。
- 任意虚拟交易都能找到对应信号和策略版本。
- 相同信号无法产生重复成交。
- T+1、部分卖出和完整周期盈亏计算正确。
- 前向模拟记录可以完整还原每次买入、补仓和卖出。
- 旧消息和实际持仓不会污染前向模拟成绩。
