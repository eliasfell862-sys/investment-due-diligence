# 东方财富实盘交易网关设计规格

日期：2026-08-17
状态：待用户最终复核
范围：证券工作台股票模块、Windows 本地交易桥、东方财富桌面客户端

## 1. 目标

在现有自选股、个股分析、短中线建议、回测信号、实际持仓、手续费、T+1、做 T、信号收件箱和策略复盘能力之上，增加受严格资金和风险边界约束的实盘交易能力。

系统采用“云端决策、手机管理、本机执行、券商结果为准”的模式。用户主要通过手机网站查看和管理交易；Windows 电脑在交易时段保持开机、联网，并运行东方财富桌面客户端和本地交易桥。

本功能不承诺收益，不绕过券商安全机制，不把券商账号密码上传云端。东方财富客户端没有面向普通个人账户的稳定公开交易 API，因此第一阶段必须先验证桌面客户端适配器的稳定性；验证失败时不得进入实盘。

## 2. 已确认的账户与风险参数

| 参数 | 规则 |
| --- | --- |
| 实盘资金池 | 7,000 元 |
| 最大投入 | 5,600 元，即资金池的 80% |
| 最低预留现金 | 1,400 元 |
| 最大同时持仓 | 2 只股票 |
| 单只持仓上限 | 原则上不超过 3,500 元，且不能突破总投入上限 |
| 单笔最大计划损失 | 140 元，包含预计买卖费用 |
| 每日熔断上限 | 当日累计已实现亏损加交易费用达到 210 元 |
| 买入单位 | 100 股的整数倍 |
| 买入范围 | 当前登录账号的自选股 |
| 初始运行 | 至少 20 笔影子订单通过后才能开启实盘 |
| 初始实盘限制 | 前 5 笔真实买入每笔最多 100 股 |

以上属于服务器和本地交易桥共同执行的硬限制。修改资金池、投入比例、单笔损失、熔断或实盘权限必须二次验证并写入审计记录。策略模型无权自动放宽这些限制。

## 3. 总体架构

```text
自选股 + 个股分析 + 短中线建议 + 回测 + 实时行情
                         |
                         v
                   云端订单决策器
        观察提醒 / 核心买点 / 普通卖出 / 硬止损
                         |
                         v
             有签名、有效期和唯一编号的交易指令
                         |
                         v
                 Windows 本地交易桥
      复核资金、持仓、价格、T+1、费用、设备与客户端
                         |
                         v
                 东方财富桌面客户端
                         |
                         v
       委托、成交、拒单、撤单和持仓结果同步回云端
```

### 3.1 云端职责

- 读取当前账号自选股及既有分析结果。
- 生成观察提醒、订单候选和风险事件。
- 保存订单意图、审批状态、执行结果、设备心跳和审计轨迹。
- 向手机网站和现有信号收件箱发送状态通知。
- 不保存券商账号、密码、交易验证码或客户端会话。
- 不把“订单已发送”视为成交，实际状态必须以券商返回结果为准。

### 3.2 本地交易桥职责

- 在 Windows 本机与已授权的东方财富桌面客户端交互。
- 使用 Windows 本地加密凭据库保存必要的本地秘密。
- 拉取已签名且未过期的订单指令。
- 独立重复执行全部硬风控，不能盲信云端计算。
- 读取券商资金、持仓、可用股份、委托和成交结果。
- 执行报单、撤单、普通卖出和已预授权硬止损。
- 将执行结果和异常同步到云端。
- 对每个幂等订单编号最多执行一次。

### 3.3 东方财富适配器边界

交易桥采用券商中立接口，东方财富只是第一版适配器。标准能力包括：

- 检测客户端版本和登录状态；
- 读取资金与持仓；
- 读取全部股份与可用股份；
- 提交限价买卖委托；
- 查询委托和成交；
- 撤销未成交委托；
- 识别弹窗、验证码、断网和客户端升级造成的未知状态。

任何关键字段无法可靠读取时，适配器必须进入“禁止下单”状态。未来可在不改动策略和风控层的情况下增加 QMT、PTrade 或其他正式券商接口适配器。

## 4. 信号与买入规则

### 4.1 观察提醒

同时满足以下条件时生成观察提醒，不直接下单：

- 股票属于当前账号自选股；
- 短线评级为“买入”；
- 中线评级至少为“观察/等待”，不能为“回避”；
- 短中线综合评分达到配置门槛；
- 实时价格进入短线建议买入区间。

提醒必须展示股票、实时价格、短线区间、正式建议买入价、短中线评级、综合评分、信号依据和行情时间。

### 4.2 核心买点自动订单

个股分析页面的正式建议买入价是核心买点。当实时价格达到或低于该价格时，电脑可以在预授权范围内自动买入，无须手机再次确认，但必须再次满足：

- 短线评级仍为“买入”；
- 中线评级仍不低于“观察/等待”；
- 综合评分未跌破门槛；
- 行情新鲜且交易状态正常；
- 不存在停牌、异常快速下跌、无法确认的涨跌停状态或数据源冲突；
- 回测样本和风险检查通过；
- 当前持仓少于 2 只；
- 资金、单股仓位、预留现金、手续费和最大损失限制均通过。

正式建议买入价是允许成交的价格上限，不是要求追价成交的目标。实时价格高于该上限时不得下单。

### 4.3 数量计算

建议股数取下列约束允许数量的最小值，再向下取整到 100 股：

1. 可投入资金允许数量；
2. 单只 3,500 元上限允许数量；
3. 单笔 140 元最大计划损失允许数量；
4. 券商实际可用资金允许数量。

风险数量使用下式计算：

```text
计划损失 = 数量 × (限价 - 初始硬止损价)
         + 预计买入费用
         + 预计卖出费用
```

若满足风险限制的数量不足 100 股，或买入后预留现金低于 1,400 元，则拒绝生成订单。默认禁止因亏损而补仓；后续加仓必须由新的独立核心买点触发，并重新通过全部限制。

### 4.4 多候选排序

资金不足以执行全部候选时，按以下顺序排序：

1. 短中线综合评分；
2. 预期收益风险比；
3. 中线评级；
4. 实时价格相对正式建议买入价的偏离；
5. 流动性与可成交性。

只执行排序最高且满足全部硬限制的候选，其余候选保留观察状态，不抢占预留现金。

### 4.5 委托价格与有效期

- 仅使用有价格保护的限价单。
- 限价不得高于正式建议买入价。
- 允许使用确认时实时卖一价和极小的可配置滑点容差，但最终仍受正式建议买入价上限约束。
- 默认有效期 30 秒。
- 未成交或部分成交后，撤销剩余委托；系统不得自动抬价追单。
- 行情过期、报价跳变、客户端状态未知或网络断开时立即拒绝执行。

## 5. 卖出、止损与 T+1

卖出相关动作的优先级固定为：

```text
硬止损
→ 清仓级风险信号
→ 第二止盈/正式清仓
→ 第一止盈/普通减仓
→ 做 T
→ 继续持有
```

高优先级状态存在时，低优先级订单自动取消。做 T 不得延迟、覆盖或削弱止损、清仓和普通减仓信号。

### 5.1 普通卖出

止盈、减仓和策略转弱等普通卖出必须先发送到手机，由用户确认后执行。确认界面必须展示：

- 卖出数量和可用数量；
- 实时价格与限价；
- 预计手续费、印花税和滑点；
- 预计实现盈亏；
- 卖出依据和信号时间。

普通卖出按以下规则生成：

- 达到第一止盈价时，持仓不少于 200 股则提醒卖出 50%，数量按 100 股向下取整；只有 100 股则提醒全部卖出。
- 第一止盈实际成交后，剩余股份的硬止损自动上移，且不得低于包含实际费用后的盈亏平衡价。
- 达到第二止盈价时，提醒卖出剩余全部股份。
- 达到个股分析页面的正式建议卖出价时，视为至少第一止盈级信号；若模型同时给出更强清仓信号，则执行更高优先级规则。
- 短中线评级转弱时必须先判断当前持仓盈亏。若持仓处于亏损状态，评级转弱本身不触发普通减仓或清仓，状态转为“亏损观察”，允许继续等待；初始硬止损不得下调，硬止损、致命风险和账户级风险规则仍保持更高优先级。
- 持仓处于盈利状态且短线转为“减仓/卖出”、中线仍为“观察/等待”时，按第一止盈规则执行：不少于 200 股提醒卖出 50%，只有 100 股提醒全部卖出，并上移剩余仓位止损。
- 持仓处于盈利状态且短线、中线同时转为“减仓/回避”时，按第二止盈规则提醒卖出剩余全部股份。
- 出现致命风险时不区分盈亏，直接进入清仓级风险流程；若同时触发硬止损，则硬止损优先。
- 同一交易日同时触发止盈和止损时，止损优先。

手机确认时必须重新读取实时价格、券商可用数量和费用。确认后的限价单默认有效 30 秒，未成交部分撤销，不得在价格变化后继续使用旧确认追单。普通部分卖出使用 100 股整数倍；清仓时允许处理不足 100 股的尾仓。实际成交后立即同步券商持仓、费用、实现盈亏和策略复盘。

### 5.2 做 T

实盘做 T 继续复用《实际持仓动态做 T 信号设计规格》的逐股动态模型和费用引擎，并增加券商执行约束：

- 只处理当前账号的真实持仓，不扫描全部 A 股。
- 做 T 卖出和回补均须手机确认，本地交易桥不得自动执行。
- 只允许卖出券商显示的可用股份。
- 单次建议数量从 100 股开始，按 100 股递增，最高不超过最新可用股份的 35%。低于 100 股时不生成做 T 信号。
- 行情或 K 线过期、流动性不足、停牌、涨跌停状态无法确认或报价异常时不生成信号。
- 同一股票存在硬止损、清仓、普通减仓、未完成卖出委托或未完成做 T 周期时，不允许新开做 T 周期。
- 必须完整计算卖出佣金、印花税、过户费、预计滑点，以及回补佣金、过户费和预计滑点。费用后预计完整周期净收益必须为正并超过风险缓冲。
- 用户确认卖出后，以券商实际成交价、数量和费用重算回补区间。
- 卖出所得优先锁定为该周期的回补资金，不能被新的自动买入订单占用。
- 回补必须至少满足一项价格条件和一项企稳条件。跌破关键支撑且风险扩大时暂停回补，不能机械接回。
- 回补数量不得超过实际已卖数量；部分成交只按已配对数量确认做 T 收益，剩余数量继续追踪。
- 做 T 周期默认仅在卖出交易日有效。临近收盘仍未回补时，用户可选择按实时价格回补、继续等待至收盘或保留为普通减仓。
- 收盘后未处理的周期不得自动跨日延续回补逻辑。
- 每日熔断后不再产生新的做 T 卖出；已经卖出的周期仍可由用户确认回补，但回补后不得超过做 T 前的原持仓数量。
- 未回补部分转为普通减仓后，只确认减仓损益，不再计作做 T 降本。

做 T 手机确认界面必须展示卖出和回补区间、建议数量、可用数量、完整双边费用、预计净收益、预计降本金额、未回补风险、信号依据和有效期。每次真实卖出或回补独立记录，支持部分成交和多次回补。

### 5.3 硬止损

- 买入订单必须同时确定初始硬止损价。
- 硬止损包含在用户开启实盘策略时的预授权范围内，触发后本地交易桥可以自动卖出。
- 止损价可随盈利自动上移，但绝不能向下放宽。
- 每次上移必须保存旧值、新值、计算依据和时间。
- 触发后使用受保护限价单；首次未成交时只允许按预设小步调整，并持续发送高优先级告警。
- 未能确认券商状态时不得重复报单。

### 5.4 T+1

- 本地交易桥以券商数据区分全部股份和可用股份。
- 当日买入股份不得卖出。
- 已有可用底仓时，只能卖出可用部分。
- 不可用股份触发硬止损时，系统立即告警并记录待处理风险；下一交易日股份可用后优先执行止损。
- 云端推算结果与券商可用数量不一致时，以券商为准并暂停新增买入，等待对账。

### 5.5 每日熔断

当日累计已实现亏损加全部交易费用达到 210 元时：

- 禁止新增买入和补仓；
- 仍允许止损、减仓、清仓和撤单；
- 不再产生新的做 T 卖出信号；
- 已经卖出的做 T 周期仍允许用户确认回补，但不得超过周期开始前的原持仓数量；
- 下一交易日自动解除；
- 收盘后生成熔断复盘；
- 用户不能通过普通订单确认绕过熔断。
## 6. 状态模型与幂等性

订单意图至少包含以下状态：

```text
observing
eligible
awaiting_mobile_approval
preauthorized
leased_by_bridge
submitting
submitted
partially_filled
filled
cancel_requested
cancelled
rejected
expired
blocked_by_risk
reconciliation_required
```

每个订单必须具有：

- 全局唯一订单意图 ID；
- 用户 ID、设备 ID 和策略版本；
- 股票、方向、数量、限价、有效期和生成行情快照；
- 风控快照和费用估算；
- 唯一幂等键；
- 云端签名和本地领取租约；
- 券商委托编号、成交编号及状态时间线。

交易桥领取订单后必须持有短期租约。重启或断网恢复时先查询券商委托状态，再决定恢复、撤销或进入对账；禁止直接重新发送相同订单。

## 7. 数据与审计

建议新增独立数据边界：

- `trading_devices`：已配对设备、公钥、状态和最后心跳；
- `live_trading_profiles`：资金池、投入上限、损失限制和模式；
- `trade_intents`：订单意图及风险快照；
- `broker_orders`：券商委托与状态；
- `broker_fills`：真实成交明细；
- `broker_position_snapshots`：券商持仓对账快照；
- `trading_audit_events`：审批、配置变更、风控、执行和异常事件。

所有表必须按用户隔离并执行 RLS。交易桥只可访问已配对用户和设备范围内的数据。敏感字段不得写入日志、错误信息或浏览器缓存。

## 8. 手机端与操作界面

证券工作台增加“实盘交易”入口，至少包括：

- 实盘总览：资金池、已投入、预留现金、可用资金、当日盈亏和熔断状态；
- 候选订单：观察提醒、等待核心买点和待确认卖出；
- 实盘持仓：全部/可用数量、成本、最新价、止损价和盈亏；
- 订单记录：委托、部分成交、成交、撤单、拒单和失效；
- 设备状态：交易桥、东方财富登录、心跳和行情新鲜度；
- 模式控制：影子模式、暂停新买入、仅允许卖出、实盘启用；
- 紧急停止：取消未成交订单并禁止新增买入，不自动卖出现有持仓。

自动买入、自动硬止损、订单拒绝、部分成交、对账失败和设备离线均必须进入现有收件箱，并提供手机通知。

## 9. 安全机制

- 首次连接使用一次性配对码和设备密钥完成绑定。
- 券商凭据仅存于 Windows 本地加密凭据库。
- 云端订单必须签名，交易桥验证签名、用户、设备、有效期和幂等键。
- 开启实盘、修改资金限制、解除暂停和更换设备需要应用安全密码二次验证。
- 电脑离线、客户端未登录、客户端版本未知、行情过期或对账失败时进入“仅提醒、禁止下单”。
- 交易桥不得开放公网入站控制端口；优先由本地主动拉取短期指令。
- 日志不得包含券商密码、验证码、完整令牌或其他可复用凭据。
- 上线前应确认东方财富客户端使用条款及券商对自动化委托的限制。

## 10. 异常处理

| 异常 | 处理 |
| --- | --- |
| 电脑或交易桥离线 | 不执行；订单过期并通知 |
| 东方财富未登录 | 禁止下单并通知重新登录 |
| 行情过期或数据源冲突 | 阻断订单，不使用缓存价格报单 |
| 客户端升级或控件变化 | 适配器进入禁止下单状态 |
| 提交超时且结果未知 | 查询券商委托，不得直接重试 |
| 部分成交 | 撤销剩余部分并按实际成交同步持仓 |
| 云端与券商持仓不一致 | 暂停新增买入，进入对账流程 |
| 可用资金不足 | 拒单并刷新资金快照 |
| 可用股份不足 | 拒绝超额卖出，保留 T+1 风险告警 |
| 达到每日熔断 | 禁止买入，保留风险卖出能力 |
| 重复订单 | 由幂等键拒绝第二次执行 |

## 11. 验证与发布阶段

### 11.1 东方财富适配性验证

先在本机验证客户端版本、登录、资金、持仓、委托、成交、撤单、弹窗、断网和升级行为。关键状态无法可靠读取时停止，不以真实资金试错。

### 11.2 影子交易

至少完成 20 笔有效影子订单。交易桥执行全部真实流程和风控，但最后不向券商提交。必须覆盖：

- 买入和撤单；
- 普通卖出和硬止损；
- 部分成交状态模拟；
- T+1 阻断；
- 手续费与资金边界；
- 断网、重启和未知状态恢复；
- 重复订单拦截。

价格、数量、费用和预期持仓变化必须与人工复核一致。任何错误股票、错误方向、重复执行或突破资金限制均为阻断性失败。

### 11.3 受限实盘

- 由用户手动开启实盘；
- 前 5 笔真实买入每笔最多 100 股；
- 每笔成交后立即与券商持仓对账；
- 任一严重异常立即回到影子模式；
- 前 5 笔无严重异常后，才开放至 5,600 元最大投入。

### 11.4 正式运行

- 盘前检查设备、客户端、账户、行情和配置；
- 盘中执行订单和风险控制；
- 收盘后复盘成交价、滑点、费用、信号质量和风控执行；
- 学习系统只能提出改进建议，不能自动扩大资金、放宽止损或增加交易权限。

## 12. 测试要求

- 领域单元测试：数量、费用、仓位、最大损失、排序、熔断和 T+1。
- 状态机测试：正常成交、部分成交、撤单、超时、未知结果和恢复。
- 幂等测试：重复消息、重启、租约过期和并发交易桥。
- 安全测试：跨用户访问、伪造签名、过期指令、设备撤销和敏感日志。
- 适配器契约测试：东方财富读取与操作能力必须符合统一券商接口。
- 本地集成测试：模拟客户端窗口、弹窗、断网和控件变化。
- 云端集成测试：RLS、订单租约、结果同步、通知和审计。
- 端到端测试：手机配置、影子订单、实盘开启、自动核心买入、普通卖出审批和硬止损。

## 13. 明确不在第一版范围内

- 全部 A 股自动选股并直接实盘；
- 融资融券、港股、美股、基金、债券和期权交易；
- 多券商账户同时执行；
- 无风险边界的全自动交易；
- 云端保存券商账号密码；
- 自动放宽止损、扩大资金池或绕过每日熔断；
- 未经 20 笔影子验证直接启用真实下单。

## 14. 验收标准

功能进入正式实盘前必须同时满足：

1. 东方财富适配器能够稳定读取资金、持仓、可用数量、委托和成交；
2. 20 笔影子订单全部通过，无错误股票、错误方向、重复执行或突破硬限制；
3. 资金池、预留现金、单股上限、140 元单笔风险和 210 元每日熔断均有自动化测试；
4. T+1、部分成交、断网恢复和未知委托状态均验证通过；
5. 券商凭据不出现在云端、浏览器包、日志或审计数据中；
6. 用户能够从手机暂停买入、切换仅卖出和执行紧急停止；
7. 实盘开启必须由用户主动操作，并能随时退回影子模式；
8. 实际成交和持仓以券商结果为准，云端能够可靠对账。
