# 自选股池中线买入建议设计规格

## 1. 目标

在证券项目的“自选股池管理”页面中，为每只股票自动生成面向未来 1–3 个月的中线买入建议。建议由确定性规则算法生成，不依赖 AI，必须可解释、可复算并适合后续审计。

本功能只扩展自选股池，不修改或削弱个股分析页面。用户点击股票代码、名称或股票行时，仍进入原有个股分析页面。

## 2. 已确认决策

- 建议周期：中线 1–3 个月。
- 运行方式：打开自选股池后自动后台分析全部股票。
- 决策来源：规则算法，不由 AI 调整最终结论。
- 技术路线：新增独立的单股中线买入建议引擎。
- 页面行为：建议逐只出现，不等待全部股票完成。
- 个股分析隔离：不修改 `StockAnalysisPage.tsx` 及其数据流、状态、路由和页面布局。

## 3. 开源算法与现有资产复用

本功能复用工程中已经引入并登记在 `app/THIRD_PARTY.md` 的能力：

- InStock（MIT）：MACD、KDJ、RSI、BOLL、MA、OBV、ATR、K线形态和交易策略。
- TradingAgents-CN（Apache 2.0）：多维投资判断的分析思想，但本功能不调用多智能体或 AI。
- 现有基本面评分：盈利能力、成长性、估值水平和风险质量。

复用模块：

- `technical-indicators.ts`
- `trading-strategies.ts`
- `kline-patterns.ts`
- `fundamental-scorer.ts`
- `fetchEastmoneyKLine`
- `fetchEastmoneyBasic`

第一版不将 `backtest-engine.ts` 的输出计入最终评分。该回测使用统一的通用进出场条件，尚未证明适用于不同行业，避免把可能过拟合的历史结果包装成当前买入结论。

## 4. 模块边界

### 4.1 中线买入建议引擎

新增 `app/src/engines/market-analysis/medium-term-buy-advice.ts`。

职责：

- 接收实时行情、K线、可选财务数据及已计算的策略和形态。
- 计算趋势、基本面、策略形态和风险四个维度的分数。
- 应用数据完整度与强风险约束。
- 输出稳定的建议档位、综合分、置信度、主要依据和风险提示。

引擎是纯计算模块，不直接访问网络或 localStorage。

建议输出结构：

```ts
export type MediumTermAdviceAction =
  | 'accumulate'
  | 'cautious_buy'
  | 'watch'
  | 'avoid_buying'
  | 'risk_avoidance'
  | 'insufficient_data';

export interface MediumTermBuyAdvice {
  code: string;
  horizon: '1_3_months';
  action: MediumTermAdviceAction;
  label: '分批买入' | '谨慎买入' | '观察等待' | '暂不买入' | '风险回避' | '数据不足';
  score: number;
  confidence: number;
  confidenceLabel: '高' | '中' | '低';
  reasons: string[];
  risks: string[];
  dataCompleteness: {
    quote: boolean;
    kline: boolean;
    fundamental: boolean;
  };
  calculatedAt: string;
}
```

### 4.2 自选股建议调度服务

新增 `app/src/features/securities/watchlist-buy-advice-service.ts`。

职责：

- 为当前自选股池创建后台分析队列。
- 同时最多分析 4 只股票。
- 并行获取单只股票的约 120 个交易日 K线和财务数据。
- 克隆 K线后再调用 `calcAllIndicators`，避免原地修改影响其他消费者。
- 调用策略、形态、基本面和中线建议引擎。
- 支持单只股票重试。
- 切换自选股池后忽略旧队列返回的结果。
- 缓存完成结果，减少重复请求。

服务不能导入或调用个股分析页面组件。

### 4.3 自选股池页面

修改 `WatchlistPage.tsx`，只负责：

- 启动当前股池的建议队列。
- 维护每只股票的等待、分析、成功和失败状态。
- 渐进式渲染结果。
- 展开或收起建议详情。
- 保留股票行原有跳转行为。

如果页面文件因新增状态和渲染继续膨胀，可将建议列提取为独立展示组件，但不做与本功能无关的页面重构。

## 5. 数据流

```text
自选股行情加载完成
  → 检查四小时缓存
  → 未命中的股票进入并发队列
  → 获取120日K线 + 财务数据
  → 克隆K线并计算技术指标
  → 扫描交易策略与K线形态
  → 计算基本面评分
  → 中线建议引擎生成结果
  → 对应股票行立即显示建议
  → 写入缓存
```

缓存使用独立键 `sec_watchlist_buy_advice_cache_v1`，不得修改 `sec_watchlists_v2` 和 `sec_active_watchlist`。缓存有效期为 4 小时，手动刷新时忽略当前股池的缓存并重新计算。

## 6. 评分模型

综合分范围为 0–100：

| 维度 | 权重 | 核心信息 |
|---|---:|---|
| 趋势与技术指标 | 35 | MA20/MA60、MACD、RSI、KDJ、BOLL、成交量、ATR |
| 基本面与估值 | 30 | ROE、营收增长、利润增长、PE、PB、负债率、股息率 |
| 交易策略与K线形态 | 20 | InStock 买卖策略、突破和多空反转形态 |
| 风险与流动性 | 15 | 市值、换手率、波动率、强看空信号、数据异常 |

建议档位：

| 分数 | 建议 |
|---:|---|
| 78–100 | 分批买入 |
| 68–77 | 谨慎买入 |
| 55–67 | 观察等待 |
| 40–54 | 暂不买入 |
| 0–39 | 风险回避 |

综合分表示多空与质量倾向，置信度表示数据完整度和多个维度的一致程度，二者不得混为同一指标。

## 7. 硬约束与降级规则

- K线不足时不得输出“分批买入”。
- 基本面数据缺失时最高只能输出“谨慎买入”，并降低置信度。
- 存在强卖出策略或多个强看空形态时，结果至少降为“观察等待”。
- 停牌、价格无效或关键数据异常时输出“数据不足”。
- K线请求失败时不凭单日涨跌给出明确买入结论。
- 财务请求失败时允许生成技术面建议，但必须标记基本面数据缺失。
- 单只股票失败不得中断其他股票的分析。
- `reasons` 和 `risks` 分别最多显示 3 条，优先保留强度最高且不重复的依据。
- 第一版不输出精确目标价格和收益预测，避免虚假精度。

## 8. 页面交互

股票表格在“市值”之后、“标签”之前新增“中线建议”列。

紧凑状态示例：

```text
分批买入 82分
置信度：高
```

建议状态同时使用文字和颜色：

- 分批买入：金色。
- 谨慎买入：浅金色。
- 观察等待：蓝绿色。
- 暂不买入：橙色。
- 风险回避：红色。
- 数据不足：灰色。

页面顶部显示当前进度和“刷新全部建议”：

```text
中线建议分析：18 / 36
[刷新全部建议]
```

交互规则：

- 点击股票代码、名称或股票行，仍跳转到原有个股分析页面。
- 点击“中线建议”单元格时调用 `stopPropagation()`，仅展开或收起当前行的只读详情。
- 详情展示综合分、置信度、主要依据、风险提示、数据完整度和计算时间。
- 单只股票失败显示“重试”，只重新分析该股票。
- 建议尚未完成时显示“等待分析”或“分析中”。
- 不新增弹窗，不调用 AI。

## 9. 个股分析隔离要求

- 不修改 `StockAnalysisPage.tsx`。
- 不修改个股分析的路由结构。
- 不修改个股分析的状态、标签页和数据加载流程。
- 不改变现有 `technical-indicators.ts`、`trading-strategies.ts`、`kline-patterns.ts`、`fundamental-scorer.ts` 的公开行为。
- 不修改行情和K线接口语义；仅调用现有公开函数。
- 新服务不得共享个股页面的 React 状态或可变 K线对象。
- 点击股票行的跳转地址必须保持 `/projects/:projectId/securities/stock/:code`。

## 10. 错误处理

- 缓存损坏时忽略缓存并重新计算，不让页面崩溃。
- 某只股票请求超时或接口失败时显示该股票的错误状态和重试入口。
- 股池切换时旧请求可以自然完成，但其结果不得写入新股池的页面状态。
- 页面卸载后不得继续更新 React 状态。
- 手动刷新期间保留现有建议，直到新结果逐只替换，避免整张表闪空。
- 缓存写入失败不影响当前会话显示。

## 11. 测试要求

### 11.1 纯引擎测试

- 多维看多且数据完整时输出“分批买入”。
- 基本面缺失时不能输出“分批买入”。
- 强卖出策略或多个强看空形态触发降档。
- K线不足或价格无效时输出“数据不足”。
- 分数始终限制在 0–100。
- 依据和风险分别不超过 3 条。
- 置信度随数据缺失下降。

### 11.2 调度服务测试

- 最大并发数不超过 4。
- 缓存命中时不重复请求。
- 缓存过期时重新计算。
- 单只股票失败不影响其他股票。
- 切换股池后旧任务结果被忽略。
- K线在计算指标前被克隆。

### 11.3 页面测试

- 行情加载完成后自动启动建议分析。
- 建议逐只显示并更新进度。
- 点击建议单元格不会导航。
- 点击股票行仍进入原有个股分析地址。
- 单股失败可以重试。
- 刷新全部建议会绕过缓存。

### 11.4 个股分析回归

- 个股概览指标正常显示。
- K线、均线和技术指标正常显示。
- 基本面、策略、资金流及回测标签仍可使用。
- 个股页面控制台无新增错误。

## 12. 范围外事项

- 不使用 AI 生成或调整买入建议。
- 不输出精确目标价、保证收益或自动交易指令。
- 不接入券商账户或执行交易。
- 不修改个股分析页面。
- 不将通用回测结果计入第一版评分。
- 不建立跨设备云同步。

## 13. 完成标准

- 自选股池中的每只有效股票均能自动进入建议分析队列。
- 页面逐只显示中线建议、分数和置信度。
- 用户能够展开可解释的依据和风险。
- 数据缺失或失败时明确降级，不给出过度确定的结论。
- 点击股票行仍能正常进入个股分析页面。
- 个股分析页面功能、K线和概览不受影响。
- 新增目标测试、证券相关回归、类型检查和生产构建完成。
