# 本机加密 AI Agent 模型配置设计规格

## 1. 目标

在应用左侧主导航新增独立的“AI Agent 配置”模块，让客户选择自己的后端大模型、填写自己的 API Key，并将该配置用于平台的投研尽调和证券 AI 分析功能。

API Key 仅保存在当前电脑，不上传 Supabase，不跨设备同步。Key 必须通过客户设置的独立密钥库密码加密保存；刷新或关闭页面后重新锁定，解密后的 Key 只存在于当前页面会话的内存中。

本功能只统一 AI 能力的配置和调用入口，不修改行情、K 线、估值、风险、回测等确定性引擎，也不改变个股分析页面的非 AI 算法。

## 2. 已确认的产品决策

- 左侧栏新增与“投研项目”“证券项目”并列的 `03 AI Agent 配置`。
- 使用“全站默认模型 + 功能覆盖”模式。
- API Key 仅保存在当前电脑。
- 使用独立的本机 AI 密钥库密码加密 API Key。
- 首版供应商包括：DeepSeek、Kimi、通义千问、智谱 GLM、豆包、OpenAI、Ollama、自定义 OpenAI 兼容接口。
- 浏览器直接调用客户选择的供应商，不默认经过平台服务器代理。
- 首版功能覆盖组为“投研尽调 AI”和“证券分析 AI”。
- 旧的明文 AI 配置只有在用户确认后才迁移，迁移成功后删除明文 Key。

## 3. 范围

### 3.1 本阶段包含

- AI Agent 配置主导航和独立页面。
- 本机加密密钥库的创建、解锁、锁定、清空和改密入口。
- 供应商、模型、Endpoint 和生成参数配置。
- 全站默认模型和两个功能覆盖组。
- 连接测试、错误分类和配置状态展示。
- 统一 AI Gateway 和供应商适配层。
- 现有 AI 功能逐步改为通过统一 Gateway 读取配置。
- 旧 `dd-research-config` 明文配置的确认式迁移。
- 按当前登录用户隔离本机密钥库。

### 3.2 本阶段不包含

- 将 API Key 上传或同步到 Supabase。
- 平台托管客户 API Key。
- Netlify Function 或其他平台服务器代理客户请求。
- 机构管理员集中下发模型或 Key。
- 团队共享密钥库。
- AI 用量计费和平台转售模型 Token。
- 自动选择最低价模型或自动跨供应商故障切换。
- 修改基金数据源、股票行情、K 线或确定性分析算法。

## 4. 方案选择

采用“浏览器本机加密密钥库 + 直接调用模型接口”。

不采用 Netlify 后端代理，因为客户 Key 和业务数据会经过平台服务器，与“Key 仅保存在当前电脑”的隐私目标冲突。不采用必须额外安装的本地 AI 网关程序，因为它会提高首版部署和商业推广门槛。

对于禁止浏览器跨域调用的供应商，页面明确提示客户使用其自有的 OpenAI 兼容 HTTPS 网关地址。系统不得在未告知客户的情况下把请求转发到平台服务器。

## 5. 页面与导航

### 5.1 左侧主导航

主导航顺序：

1. `01 投研项目`
2. `02 证券项目`
3. `03 AI Agent 配置`

AI Agent 配置使用独立顶层路由 `/ai-agents`。该页面与投研、证券页面相互独立，但向二者提供统一 AI 配置。

在启用多用户登录的生产环境中，`/ai-agents` 必须登录后访问。退出登录时立即清除内存中的解密 Key 并锁定密钥库。

### 5.2 页面区域

页面分为四个主要区域：

1. 密钥库状态
   - 未创建：创建密钥库。
   - 已锁定：输入密钥库密码解锁。
   - 已解锁：显示锁定、改密和清空入口。
2. 全站默认模型
   - 供应商。
   - 模型名称。
   - Endpoint。
   - API Key 状态。
   - 温度。
   - 最大输出 Token。
3. 功能覆盖
   - 投研尽调 AI。
   - 证券分析 AI。
   - 每组可选择“继承全站默认”或指定独立供应商、模型和 Key。
4. 连接测试
   - 测试所选模型。
   - 显示成功状态、响应延迟、实际模型标识和简短响应。
   - 显示可理解的失败类型。

API Key 保存后只显示掩码和尾部四位，不能再次显示完整 Key。客户只能替换或删除 Key。

## 6. 供应商与模型

### 6.1 供应商预设

首版预设：

- DeepSeek
- Kimi / Moonshot
- 通义千问 / DashScope
- 智谱 GLM
- 豆包 / 火山方舟
- OpenAI
- Ollama
- 自定义 OpenAI 兼容接口

每个预设定义：

- 稳定的供应商 ID。
- 显示名称。
- 默认 Endpoint。
- 默认模型。
- 是否需要 API Key。
- 是否允许浏览器直接调用。
- 请求和响应适配器。
- 错误响应解析器。

供应商预设不能包含平台私有 Key。

### 6.2 自定义接口

自定义接口必须兼容 OpenAI Chat Completions 请求和响应格式，并允许客户填写：

- HTTPS Endpoint。
- 模型名称。
- API Key。
- 可选的自定义请求头名称，但不得允许覆盖 `Host`、`Origin`、`Content-Length` 或浏览器禁止设置的请求头。

自定义远程 Endpoint 必须使用 HTTPS。只有明确选择 Ollama 时允许 `http://localhost` 或 `http://127.0.0.1`。

## 7. 配置继承

配置解析顺序：

1. 精确任务配置。
2. 所属功能覆盖组。
3. 全站默认配置。

首版界面只允许客户编辑全站默认和两个功能覆盖组，但内部使用稳定任务标识，为后续精细配置保留扩展能力。

投研尽调任务标识至少包括：

- `due_diligence.reasoning`
- `due_diligence.research`
- `document.extraction`

证券分析任务标识至少包括：

- `securities.stock_analysis`
- `securities.watchlist`
- `securities.portfolio`
- `securities.multi_agent`

未设置覆盖时必须明确继承全站默认，不能静默使用代码中的旧模型默认值。

## 8. 本机加密密钥库

### 8.1 加密方案

- 使用浏览器原生 Web Crypto API。
- 密钥库密码通过 PBKDF2 派生 AES-GCM 加密密钥。
- PBKDF2 使用 SHA-256、随机 salt 和不少于 310,000 次迭代。
- AES-GCM 使用 256 位密钥和每次加密独立生成的 96 位随机 IV。
- 每次修改密钥数据都重新生成 IV。
- IndexedDB 只保存密文、salt、IV、算法版本、密码校验密文和非敏感配置。
- 密钥库密码和派生密钥不得持久化。
- 解密后的 API Key 只保存在内存中。

算法参数必须带版本号，以便以后迁移加密参数。升级算法时必须在客户成功解锁旧密钥库后重新加密，不能要求读取或上传明文 Key。

### 8.2 密钥库生命周期

- 首次创建时要求输入并确认密钥库密码。
- 密钥库密码至少 10 位。
- 刷新页面、关闭标签页、退出登录或会话失效时自动锁定。
- 页面处于后台超过 30 分钟后自动锁定。
- 客户可以手动立即锁定。
- 连续 5 次解锁失败后，等待 30 秒才允许再次尝试。
- 失败计数只用于当前页面会话，不持久化密码或密码摘要。
- 忘记密钥库密码时无法恢复 Key，只能二次确认后清空密钥库并重新配置。

### 8.3 用户隔离

密钥库命名空间使用当前 Supabase `user.id`。同一浏览器中的不同登录账户不能读取、覆盖或自动继承对方密钥库。

如果应用处于明确支持的未登录本地模式，则使用独立的 `local-guest` 命名空间。访客密钥库不能在用户登录后自动迁移，必须经过客户确认。

## 9. 统一 AI Gateway

### 9.1 职责

所有 AI 功能通过统一 Gateway 发起请求。功能模块只提供：

- 任务标识。
- 系统提示词。
- 用户输入或结构化业务数据。
- 期望输出格式。
- 超时和最大 Token 上限。

Gateway 负责：

- 根据任务标识解析有效配置。
- 检查密钥库是否解锁。
- 从内存密钥容器读取相应 Key。
- 调用供应商适配器。
- 规范化请求、响应、Token 用量和错误。
- 返回供应商、模型、耗时和数据质量元信息。

功能模块不得直接读取 IndexedDB 密文，也不得自行拼接 Authorization 请求头。

### 9.2 供应商适配器

每个适配器只负责一个供应商协议。适配器统一输出：

- 文本或结构化内容。
- 供应商 ID。
- 实际模型名称。
- 输入和输出 Token 数；供应商未返回时标记未知。
- 请求耗时。
- 规范化完成原因。

Ollama 不需要 Key，但仍通过 Gateway 调用，以保证配置继承、超时和错误处理一致。

### 9.3 请求数据

客户业务数据只在客户明确触发 AI 分析时发送。页面必须显示当前将使用的供应商和模型。

Gateway 不记录完整提示词、完整模型响应、客户财务原文或 API Key。调试模式也不能打印 Authorization 请求头。

## 10. 现有功能迁移

当前 `ResearchPage` 和多处 AI 功能直接读取 `dd-research-config` 并自行请求模型。迁移按以下顺序执行：

1. 建立密钥库、配置解析器和 Gateway。
2. 迁移投研尽调综合推理、研究和文档抽取。
3. 迁移证券个股 AI 分析、自选股 AI 建议和持仓配置。
4. 迁移多 Agent 辩论和策略学习中的大模型调用。
5. 删除各功能对明文 `apiKey` 的直接读取。

迁移过程中，尚未迁移的功能可以继续使用旧逻辑，但页面必须明确标记。正式切换后不得保留两个互相冲突的配置来源。

## 11. 旧配置迁移

检测到 `localStorage['dd-research-config']` 时：

1. 只显示发现的供应商、模型和 Endpoint，不回显完整 Key。
2. 提示客户创建或解锁密钥库。
3. 显示“导入现有 AI 配置”确认项。
4. 客户确认后，将配置写入全站默认模型并加密保存 Key。
5. 读取新密钥库并核对供应商、模型和 Key 尾部四位。
6. 核对成功后删除旧 `dd-research-config`。

迁移失败时保留旧配置，显示失败原因并允许重试。不得在部分写入后删除旧明文配置。

## 12. 连接测试

连接测试使用最小请求，不发送客户项目、财务或持仓数据。测试提示词固定为要求模型返回短文本 `OK`。

成功结果显示：

- 供应商。
- 实际模型。
- 响应延迟。
- 返回内容是否符合预期。
- 测试时间。

只有最近一次连接测试成功的配置可以标记为“已验证”。客户仍可保存未验证配置，但使用前必须看到明确的“未验证”状态；系统不能声称连接可用。

## 13. 错误处理

统一错误类别：

- `vault_locked`：密钥库未解锁。
- `missing_key`：需要 Key 但未配置。
- `invalid_key`：401 或供应商等价错误。
- `permission_denied`：账户无模型权限。
- `insufficient_balance`：余额或额度不足。
- `rate_limited`：频率限制。
- `model_not_found`：模型名称无效或未开通。
- `cors_blocked`：浏览器跨域阻断。
- `timeout`：请求超时。
- `network_error`：网络不可用。
- `invalid_response`：供应商返回格式不符合预期。
- `provider_error`：未分类供应商错误。

错误提示必须为可理解的中文，并保留非敏感的供应商错误摘要。错误内容不得包含 Key、Authorization 请求头或完整客户数据。

AI 调用失败不能阻塞估值、风险、回测、行情和其他确定性引擎。系统不得未经客户确认自动切换到另一个可能产生费用的模型。

## 14. 审计与隐私

本机可记录以下非敏感元数据：

- 当前用户 ID 的不可逆本机命名空间标识。
- 任务标识。
- 供应商和模型。
- 调用开始时间和耗时。
- 成功或规范化错误类别。
- Token 用量。
- 配置版本。

不得记录：

- API Key 或 Key 前缀。
- 密钥库密码、派生密钥、salt 和 IV 的组合导出。
- Authorization 请求头。
- 完整提示词和完整响应。
- 客户完整财务、持仓或尽调原文。

Key 尾部四位只用于配置页面识别，不写入调用日志。

## 15. 状态与并发

- 密钥库解锁状态仅属于当前标签页会话。
- 同一账户打开多个标签页时，每个标签页分别解锁，避免通过跨标签广播传播明文 Key。
- 配置密文更新后，其他标签页只接收“配置已变化”事件并重新锁定，不接收解密内容。
- AI 请求执行中锁定密钥库时，已经构造并发出的请求可以完成；后续重试必须重新解锁。
- 保存配置使用单写操作，不能先删除旧密文再写新密文。

## 16. 测试要求

### 16.1 加密与存储

- 正确密码可以解锁并恢复全部 Key。
- 错误密码不能产生部分明文。
- 相同 Key 两次加密产生不同密文。
- IndexedDB 和 localStorage 中搜索不到明文 Key。
- 刷新页面后内存 Key 消失并回到锁定状态。
- 不同用户命名空间互不可见。
- 清空密钥库后密文和内存 Key 均删除。

### 16.2 配置继承

- 未设置覆盖时使用全站默认。
- 投研覆盖不影响证券任务。
- 证券覆盖不影响投研任务。
- 覆盖配置删除后恢复继承默认配置。
- 未配置有效默认时返回明确的未配置错误。

### 16.3 供应商

- 每个预设产生正确 Endpoint、模型和认证头。
- Ollama 不发送 Authorization 头。
- 自定义远程 HTTP Endpoint 被拒绝。
- 本机 Ollama HTTP Endpoint 被允许。
- 401、403、404、429、余额不足、超时和 CORS 错误正确分类。

### 16.4 UI 与路由

- 左侧栏显示 `03 AI Agent 配置`。
- 未登录用户访问 `/ai-agents` 时跳转登录页。
- 密钥库锁定时不显示配置 Key。
- Key 只显示尾部四位。
- 忘记密码清空流程需要二次确认。
- 连接测试不包含客户业务数据。

### 16.5 回归

- 个股行情和 K 线正常加载。
- 估值、风险、回测等非 AI 引擎在密钥库锁定时继续工作。
- 基金、债券和 ETF 模块不因本功能改变数据源。
- 生产构建不包含任何测试 Key 或平台私有 Key。

## 17. 验收标准

- 客户可以从左侧主导航进入独立 AI Agent 配置页。
- 客户可以创建和解锁本机加密密钥库。
- 客户可以配置八类供应商和自定义 OpenAI 兼容接口。
- 客户可以设置全站默认模型，并为投研尽调和证券分析分别覆盖。
- 客户可以在不发送业务数据的情况下测试连接。
- 刷新、退出登录或会话失效后密钥库自动锁定。
- IndexedDB、localStorage、Supabase、日志和构建产物中不存在明文 API Key。
- 已迁移 AI 功能通过统一 Gateway 调用，不再自行读取明文 Key。
- 旧明文配置只有在确认和核验成功后才删除。
- AI 不可用时，确定性分析引擎和个股行情页面仍正常工作。
