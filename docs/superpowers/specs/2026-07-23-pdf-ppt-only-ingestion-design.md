# PDF/PPT 独立入口与候选证据工作流设计

**日期：** 2026-07-23  
**状态：** 已完成分段确认，等待书面规格复核  
**适用范围：** 一级市场投资尽调模型 v1 本地网页工具

## 1. 目标

Excel 不再是项目进入分析链路的必要条件。用户只上传 PDF 或 PowerPoint 时，系统也必须能够在本机保存材料、提取可读内容、生成带来源定位的候选证据、支持投资者确认或修正、补充结构化字段，并据此计算准备度、生成项目速览报告。

系统不得把未确认的机器提取结果当作事实，不得因缺少财务数据而编造估值、IRR、MOIC、盈利预测或损失概率。

## 2. 设计原则

1. 默认离线：文件、解析结果、审核记录和正式证据保存在本机 IndexedDB，不因解析而发起网络请求。
2. Excel 非必需：PDF/PPT-only 项目与 Excel 项目使用同一正式证据库、冲突规则和分析引擎。
3. 三层隔离：原始片段、候选证据和正式证据分开保存，未经审核的候选项不能进入正式计算。
4. 来源可追溯：每个正式事实能够回到具体文件、页码或幻灯片及原文位置。
5. 解析失败可继续：任何解析失败都不能阻止原文件存档、手动补录或项目速览报告工作流。
6. 保守处理冲突：冲突不能通过删除或选择单一来源被掩盖；分析层按指标方向使用保守值，并要求投资者确认。
7. 事实与假设分离：管理层预测、投资者假设、人工访谈和历史事实使用不同来源类型和披露方式。
8. AI 可选：配置 API Key 后可提供语义识别增强，但 AI 结果仍是候选证据，不改变默认本地运行能力。

## 3. 方案选择

采用“本地确定性提取 + 候选证据确认 + 可选 AI 增强”的双层方案。

- 第一层在浏览器中完成文件读取、文字和表格提取、来源定位、关键词与规则匹配、候选项生成。
- 第二层由用户主动启用联网 AI，对已经提取的最小必要文本进行语义分类或字段建议。联网结果必须标记模型、时间和来源，且必须经过人工确认。
- 不在 v1 引入必须安装的 Python 服务或桌面后台进程，以保持浏览器直接运行和本地数据优先的产品定位。

## 4. 支持范围

### 4.1 PDF

- 文本型 PDF：提取逐页文字、段落和可识别表格。
- 扫描版 PDF：直接提取未发现有效文本时，显示原因并允许用户按页启动本地 OCR。
- 混合 PDF：正常解析文本页，仅对缺少有效文本的图片页提供 OCR。
- 来源定位至少保留页码和原文片段；解析能力允许时保留页面坐标、表格编号、行列位置。
- 密码保护、损坏或超出资源限制的 PDF 保持存档状态，并进入手动补录工作流。

### 4.2 PowerPoint

- `.pptx`：解析每张幻灯片的可见文字、表格、备注、图表标题和标签。
- 如果能够安全读取图表内嵌数据，可生成候选数据；若只有渲染图片，不依据图形高度或视觉比例猜测数值。
- PPTX 中的图片允许按单页启动本地 OCR。
- 旧版 `.ppt`：v1 仅存档、提示另存为 `.pptx`，并提供手动录入；不在浏览器中直接解析旧二进制格式。
- 来源定位至少保留幻灯片编号、对象类型和原文片段；解析能力允许时保留对象标识、名称、区域和表格行列位置。

### 4.3 OCR

- OCR 默认不自动运行，仅在直接文本提取失败或用户主动选择页面时启动。
- OCR 在本地执行，按页显示排队、运行、完成、失败、暂停或取消状态。
- OCR 结果默认具有低于直接文本提取结果的置信度，必须确认后才能进入正式证据库。
- OCR 和 AI 生成内容始终保留机器生成标记。

## 5. 数据模型

### 5.1 `SourceFragment`

保存解析得到的原始内容，不表达该内容是否为真实事实。

建议字段：

- `id`、`projectId`、`documentId`、`documentVersionId`
- `sourceKind`：`pdf_text`、`pdf_table`、`ppt_text`、`ppt_table`、`ppt_notes`、`embedded_chart_data`、`ocr`
- `pageNumber` 或 `slideNumber`
- `objectId`、`objectName`、`tableRow`、`tableColumn`、`boundingBox`
- `rawText`、`normalizedText`
- `extractionMethod`、`extractionVersion`
- `contentHash`、`createdAt`

### 5.2 `EvidenceCandidate`

表示系统从一个或多个原始片段中识别出的结构化候选值。

建议字段：

- `id`、`projectId`、`fieldId`
- `normalizedValue`、`displayValue`、`unit`
- `periodIdentity`、`dimensionIdentity`
- `sourceFragmentIds`
- `recognitionMethod`：`rule`、`ocr_rule`、`ai_assisted`
- `confidence`
- `reviewStatus`：`pending`、`confirmed`、`corrected`、`rejected`、`conflicted`
- `originalCandidateValue`、`correctedValue`
- `reviewedAt`、`reviewReason`
- `candidateFingerprint`、`createdAt`、`updatedAt`

### 5.3 `EvidenceItem`

沿用现有正式证据模型，由已确认或已修正候选项生成。新增或明确以下来源信息：

- `sourceDocumentId`
- `sourceFragmentIds`
- `sourceLocator`
- `sourceType`：`document_fact`、`management_forecast`、`investor_assumption`、`interview`
- `candidateId`
- 人工修正审计信息

正式证据继续进入现有 EvidenceRepository、冲突分组、方向感知保守值和 readiness 计算。

## 6. 文件与解析状态

文件列表显示以下解析状态：

`未解析 → 解析中 → 待审核 → 部分完成 → 已完成`

异常分支为 `解析失败`。失败文件仍然可以重新解析、按页 OCR、跳过解析或手动补录。

文件内容变化时创建新文档版本，不覆盖旧版本。旧正式证据继续指向原版本，除非用户明确用新版本重新审核并替换。

## 7. 候选证据审核页面

审核工作台采用三栏结构：

1. 左栏：文件目录、PDF 页码或 PPT 幻灯片列表，以及解析状态。
2. 中栏：原文或页面预览，高亮当前候选项对应的句子、表格单元格或图片区域。
3. 右栏：结构化候选表单，显示字段、值、单位、期间、业务维度、来源、提取方法和置信度。

候选项操作：

- 确认：候选值原样转入正式证据库。
- 修正：填写修正值和原因，保留原文及原始识别值后转入正式证据库。
- 拒绝：保留拒绝记录，不进入计算。
- 标记冲突：加入相同项目、字段、期间和维度的冲突组。
- 稍后处理：维持待确认状态，不计入数据完整度。

## 8. 手动补录

候选审核和手动补录共用结构化字段组件，不把人工入口隐藏在解析失败页。

- 可以从候选片段一键带入表单，也可以完全手动新增。
- 可以使用当前行业模板字段、组合其他行业模板字段或新增项目级自定义指标。
- 文档事实必须选择文件和来源位置。
- 无文档来源的内容必须选择“人工访谈”或“投资者假设”，并填写说明。
- 投资者假设只能用于预测、估值和敏感性分析，不能伪装成历史实际值。
- 管理层预测必须与历史实际数据分开存储、显示和报告披露。

## 9. 冲突与保守值

同一项目、字段、期间和维度存在多个不同正式证据值时，系统建立冲突组：

- 不允许通过删除某个来源来隐藏冲突。
- 在用户最终确认前，分析层按指标方向采用保守值。
- 正向指标采用较低值，负向指标采用较高值；中性、类别或不可比较值阻止确定性结论。
- 报告并列披露各来源、原始口径、保守分析值和待验证动作。
- 重大未解决冲突阻止正式投资备忘录，但不阻止项目速览报告。

## 10. 准备度与报告

准备度按模块计算，不依赖是否上传 Excel：

- 公司与业务
- 团队与治理
- 行业与竞争
- 产品与技术
- 财务与单位经济
- 融资与股权
- 风险与退出
- 估值与回报

未确认候选项不计入准备度。OCR 候选项确认后可计入，但保留较低证据置信度。缺失资料产生“资料不足风险”和尽调问题，不自动降低项目业务质量分。

### 10.1 项目速览报告

已有文件并确认部分核心证据后即可导出。内容包括已确认事实、待确认候选项、缺失数据、证据冲突、初步亮点、初步风险、下一轮尽调问题和当前无法计算的指标。

### 10.2 正式投资备忘录

关键事实、财务、融资条款和估值假设达到要求，且不存在阻断性未解决冲突时，才允许生成确定性投资结论。

新增投资判定：`资料不足，暂缓决策`。该判定与“拒绝投资”分开，适用于核心数据不足、重大证据待确认或估值回报无法可靠计算的项目。

### 10.3 禁止伪精确

- 无可靠财务数据时，不输出虚构的 DCF、IRR、MOIC 或本金损失概率。
- 如果 BP 仅提供管理层预测，报告必须清晰标记预测来源，不将其表示为历史业绩。
- 无法计算的指标显示缺失原因、所需资料和验证动作。
- 所有投资结论采用“证据 → 指标 → 比较标准 → 投资含义 → 建议动作”的逻辑链。

## 11. 资源与安全限制

- 单个文件保持 100 MiB 上限。
- PDF 默认最多自动解析 500 页。
- PPTX 默认最多自动解析 500 张幻灯片。
- OCR 按页运行，可暂停或取消；超大图片在不修改原文件的前提下缩放后识别。
- PDF/PPTX 解压、文本提取和 OCR 放在 Web Worker 中运行。
- 对压缩比、解压后总体积、对象数量、图片像素、执行时间和 Worker 消息大小设置上限。
- 每个文件独立解析，一个文件失败不影响同批次其他文件。
- 解析事务成功前不更新文件为完成状态，不覆盖已确认正式证据。
- 默认解析路径不得调用 `fetch` 或把文件内容发送到网络。

## 12. 幂等、版本和审计

- 使用文档内容指纹、来源位置、目标字段和规范化值生成候选指纹。
- 重复解析相同文件不重复生成相同候选项。
- 已确认、已修正或已拒绝候选项不得因重新解析自动恢复为待确认。
- 文件版本变化产生新候选项，并保留与旧版本之间的关联。
- 修正记录包含原始值、修改值、修改时间、修改原因和来源片段。
- 删除文件前必须提示其被哪些正式证据引用；v1 不允许静默级联删除正式证据。

## 13. 错误处理

系统应区分并明确提示：

- 文件损坏或格式不匹配
- 密码保护 PDF
- 旧版 `.ppt` 不可直接解析
- 超出页数、幻灯片数、解压大小或图片像素限制
- Worker 超时或内存不足
- 本地存储配额不足
- 未提取到有效文本
- OCR 模型不可用或单页识别失败

所有错误均提供下一步动作：重新解析、选择页面 OCR、另存格式、手动补录或仅存档。

## 14. 验收标准

1. 仅上传一个文本型 PDF，可提取候选项、审核并进入准备度计算。
2. 仅上传一个 PPTX，可从文字和表格生成带幻灯片定位的候选项。
3. 扫描 PDF 可以按需本地 OCR，未经确认的 OCR 候选项不进入正式计算。
4. 旧版 `.ppt` 可以存档、提示转换，并可手动录入。
5. 同一收入指标在 BP 多处出现不同值时形成冲突组，并按方向感知保守规则分析。
6. 用户修正候选值后，原始值、来源和修改原因仍可追溯。
7. 没有 Excel 也能导出项目速览报告。
8. 财务资料不足时，系统不生成伪造估值、IRR、MOIC 或损失概率。
9. 默认 PDF/PPT 解析路径不发起网络请求。
10. 重新导入、重新解析和页面刷新后，不产生重复候选或跨项目数据污染。
11. 一个文件解析失败不影响其他文件的保存和解析。
12. 项目速览和正式投资备忘录采用不同的导出门槛。

## 15. v1 非目标

- 不直接解析旧版二进制 `.ppt`。
- 不承诺复杂扫描表格达到人工录入级准确率。
- 不根据图表视觉形状猜测缺失数值。
- 不让 AI、OCR 或规则引擎绕过人工确认直接形成正式事实。
- 不引入必须安装的本地后台服务。
- 不因缺失数据自动给出拒绝投资结论。
