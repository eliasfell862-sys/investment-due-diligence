# 统一实时股票行情设计规格

**日期：** 2026-08-04  
**状态：** 待最终复核  
**范围：** 证券项目中所有展示 A 股最新价格及其直接衍生数据的页面

## 1. 目标

建立统一的实时股票行情能力，使个股分析、自选股池、持仓管理等页面在交易时段自动更新最新行情，并在不重新计算重型分析结果的前提下保持各页面价格一致。

成功标准：

- 交易时段每 3 秒自动刷新一次行情。
- 午间休市、收盘、周末停止定时轮询。
- 页面重新获得焦点或从后台恢复时立即刷新。
- 所有相关页面提供“立即刷新”按钮和最后更新时间。
- 刷新失败时保留最后一次有效价格。
- 多个消费者请求同一股票时合并请求，不产生重复轮询。
- 实时行情刷新不触发中线建议、基本面评分、策略、推荐、排序或持仓方案重算。

## 2. 非目标

本阶段不包括：

- 基金净值、基金估值的实时刷新通道。
- ETF 估值、折溢价的独立实时刷新通道。
- 债券价格、收益率和估值的实时刷新通道。
- WebSocket 或付费行情源接入。
- 分时图、逐笔成交和盘口五档数据。
- 因实时价格变化而自动重跑 K 线指标、基本面评分、中线建议、股票筛选、股票推荐或持仓分配算法。

## 3. 方案选择

采用统一实时行情中心，不在每个页面分别维护定时器。

未选择的方案：

- 页面独立轮询：实现简单，但会重复请求、状态不一致且难以统一处理交易时段。
- WebSocket 推送：实时性更高，但当前免费行情源没有稳定推送接口，需要新增后端与付费数据能力。

## 4. 总体架构

新增独立的实时行情服务和 React 订阅 Hook。

### 4.1 实时行情服务

服务负责：

- 接收页面对股票代码集合的订阅和取消订阅。
- 合并所有活动订阅并对代码去重。
- 按行情接口支持的批量规模拆分请求。
- 缓存每只股票最后一次有效的 `StockQuote`。
- 记录最后成功更新时间、当前请求状态和最近错误。
- 交易时段调度、后台暂停、焦点恢复刷新和失败退避。
- 防止同一刷新周期出现重叠请求。
- 向订阅者发布发生变化的行情快照。

服务不得修改 `StockQuote` 对象；每次成功更新发布新对象，便于 React 正确检测状态变化。

### 4.2 React Hook

页面通过统一 Hook 使用行情，不直接创建 `setInterval`。

建议接口：

```ts
interface RealtimeQuoteState {
  quotes: Record<string, StockQuote>;
  refreshing: boolean;
  marketStatus: 'trading' | 'lunch_break' | 'closed' | 'weekend';
  lastUpdatedAt: string | null;
  stale: boolean;
  error: string;
  refreshNow: () => Promise<void>;
}

function useRealtimeStockQuotes(codes: string[]): RealtimeQuoteState;
```

Hook 在代码集合变化或组件卸载时更新订阅，不得遗留后台轮询。

### 4.3 现有证券工作台迁移

证券工作台现有的独立 3 秒刷新定时器迁移到统一行情中心。迁移后不得保留第二套自动刷新计时器。

## 5. 行情调度规则

时区固定按 `Asia/Shanghai` 的工作日时间判断：

- 上午交易：09:25–11:35。
- 午间休市：11:35–12:55。
- 下午交易：12:55–15:05。
- 周六、周日：周末休市。

本阶段不新增交易所节假日日历；法定节假日若落在工作日，服务仍可能按交易时段尝试请求，但失败或返回旧行情时继续保留最后有效数据。交易所日历接入作为后续行情基础设施升级项，不影响本次统一刷新机制。
- 其他时间：已收盘。

上述边界与现有证券工作台保持一致，预留开盘前后缓冲时间。

调度行为：

1. 首位订阅者出现时立即请求一次。
2. 交易时段每 3 秒请求一次。
3. 午间休市、收盘和周末不启动定时轮询，但允许手动刷新。
4. 页面从隐藏状态恢复，或窗口重新获得焦点时立即刷新一次。
5. 页面隐藏时暂停定时轮询。
6. 当前请求尚未结束时，跳过新的自动刷新，不并发发送同批请求。
7. 手动刷新若遇到正在进行的请求，复用当前请求，不创建重复请求。

## 6. 失败与数据新鲜度

### 6.1 保留旧行情

- 首次请求失败且没有缓存时，页面显示无行情错误。
- 已有有效行情时，后续失败不得清空、归零或替换旧行情。
- 单只股票未返回时，只保留该股票旧数据，不影响同批其他股票更新。

### 6.2 退避重试

连续失败后的自动重试间隔依次为：

- 3 秒
- 6 秒
- 12 秒
- 24 秒
- 最高 30 秒

任意一次成功请求后重置为正常 3 秒周期。手动刷新不受退避等待限制，但仍遵守请求防重叠规则。

### 6.3 延迟标记

最后一次成功更新时间超过 60 秒时，将行情标记为 `stale`，页面显示“行情可能已延迟”。休市状态仍显示最后更新时间，不把正常休市误报为请求失败。

## 7. 页面状态组件

提供可复用的行情状态控件，各页面使用一致文案：

- `交易中 · 3秒自动刷新`
- `午间休市`
- `已收盘`
- `周末休市`
- `刷新中`
- `最后更新：HH:mm:ss`
- `行情暂时不可用，显示上次有效数据`
- `行情可能已延迟`

控件包含“立即刷新”按钮：

- 请求期间按钮禁用。
- 点击只刷新当前页面订阅的代码。
- 不整页重载。
- 不重置标签、展开行、筛选器、表单或滚动状态。

## 8. 页面覆盖范围

### 8.1 个股分析

实时更新：

- 最新价、涨跌额、涨跌幅。
- 开盘价、最高价、最低价、昨收。
- 成交量、成交额、换手率。
- 总市值、流通市值、PE、PB。
- 以当前报价直接计算的展示值。

不自动重算：

- K 线历史序列和技术指标。
- 基本面评分、策略信号、形态、回测。
- 深度研究、辩论和 AI 结果。
- 中线建议。

现有整页刷新按钮改为行情“立即刷新”，不得调用 `window.location.reload()`。

### 8.2 自选股池

- 当前股池全部有效股票订阅实时行情。
- 标签筛选只影响展示，不改变当前股池订阅集合。
- 行情刷新不重跑中线建议。
- 中线建议继续使用自身缓存和独立刷新机制。
- 新增或删除股票后自动更新订阅集合。

### 8.3 持仓分配方案

- 当前候选组合展示实时最新价。
- 建议股数等直接依赖实时价格的展示值随行情更新。
- 已完成的评分、配比、金额和理由不自动变化。
- 用户点击“重新分析”时才重新生成完整方案。

### 8.4 持仓组管理

历史版本中的保存价格保持不可变，明确显示为“保存价格”。新增：

- 当前价。
- 当前持仓市值：`当前价 × 保存股数`。
- 浮动盈亏：`当前持仓市值 - 保存金额`。
- 收益率：`浮动盈亏 ÷ 保存金额 × 100%`。

实时行情不得回写或覆盖历史版本存储内容。

### 8.5 证券工作台股票区域

- 使用统一行情中心替代现有局部计时器。
- 自选股票列表和选中股票详情共享同一行情快照。
- 用户选择、搜索和展开状态不因刷新重置。

### 8.6 股票筛选与股票推荐

- 结果存在期间更新最新价、涨跌额、涨跌幅、市值、估值等行情字段。
- 原评分、排序、信号和推荐结论保持不变。
- 用户点击“重新筛选”或“重新分析”后才重算结果。
- 页面若没有刷新按钮，新增“立即刷新”按钮。

### 8.7 基金持仓成分股

- 基金持仓明细中已展示的 A 股最新价使用统一股票行情中心。
- 基金净值、持仓占比和基金收益率不随股票行情自动推算。

## 9. 数据一致性

- 同一代码在同一浏览器会话中使用同一份最新行情快照。
- 页面局部的旧行情对象不得覆盖行情中心的新行情。
- 新批次只合并接口实际返回且价格有效的数据。
- 缺失代码继续使用旧行情，并在内部记录缺失，不把价格设置为零。
- 代码集合排序变化不应创建无意义的新订阅；Hook 内部使用规范化、去重后的代码集合。

## 10. 性能与请求控制

- 多页面或多组件订阅同一代码时只请求一次。
- 批量请求按接口限制拆分，批次间不重复代码。
- 无活动订阅时停止自动刷新。
- 页面隐藏时不发送周期请求。
- 行情更新只通知包含发生变化代码的订阅者。
- 价格刷新不得触发 K 线、财务、AI 或建议接口。

## 11. 测试设计

### 11.1 行情服务单元测试

- 第一位订阅者触发立即请求。
- 交易时段每 3 秒刷新。
- 午间休市、收盘和周末不自动轮询。
- 页面隐藏暂停，恢复和重新聚焦立即刷新。
- 多订阅者代码去重并合并请求。
- 请求未完成时不产生重叠请求。
- 手动刷新立即请求并复用在途请求。
- 单只股票缺失不影响其他结果。
- 失败保留旧行情。
- 连续失败按 3、6、12、24、30 秒退避。
- 成功后重置退避。
- 超过 60 秒标记延迟。
- 最后订阅者卸载后停止定时器和事件监听。

### 11.2 Hook 测试

- 代码变化正确取消旧订阅并建立新订阅。
- 代码顺序变化不重复订阅。
- 卸载后不再发布更新。
- `refreshNow`、刷新状态、市场状态和错误正确透传。

### 11.3 页面集成测试

- 个股分析更新行情而不重置当前标签。
- 个股刷新按钮不再整页重载。
- 自选股池更新价格但不调用建议分析服务。
- 标签筛选不减少行情订阅代码。
- 持仓分配更新价格和建议股数，但不改变评分和配比。
- 持仓组保存价格保持不变，当前市值和盈亏计算正确。
- 股票筛选和推荐只更新行情字段，不改变排序和结论。
- 页面无刷新按钮时正确显示统一状态控件。

### 11.4 浏览器验收

依次检查：

1. 证券工作台股票区域。
2. 个股分析页面。
3. 自选股池管理。
4. 持仓分配方案。
5. 持仓组管理。
6. 股票筛选页面。
7. 股票推荐页面。
8. 基金持仓成分股明细。

每个页面确认自动刷新、手动刷新、更新时间、休市状态、失败保留旧数据和页面交互状态不重置。

## 12. 兼容与迁移约束

- 不改变 `StockQuote` 现有字段语义。
- 不改变自选股存储键 `sec_watchlists_v2` 和 `sec_active_watchlist`。
- 不修改持仓历史版本中的保存价格和保存金额。
- 不改变个股分析路由和标签结构。
- 不改变中线建议缓存和刷新规则。
- 保留当前未提交的 K 线代理修复改动，不混入本功能提交。

## 13. 交付顺序

1. 实时行情服务、交易时段规则和测试。
2. React Hook 与统一行情状态控件。
3. 证券工作台迁移。
4. 个股分析和自选股池接入。
5. 持仓分配和持仓组实时盈亏接入。
6. 股票筛选、推荐和基金持仓成分股接入。
7. 完整回归、生产构建和浏览器验收。
