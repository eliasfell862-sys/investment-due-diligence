# 自选股管理池综合评分排序设计

## 目标

自选股管理池默认按投资建议综合评分排列，使高评分、较值得关注的股票靠前，低评分以及回避或数据不足的股票靠后。

## 范围

- 仅调整自选股管理池表格的展示顺序。
- 不改变自选股在本地存储中的原始顺序。
- 不改变自选分组、回测监控范围、持仓数据或个股分析页面。
- 评分刷新完成后，列表自动依据最新结果重新排序。

## 综合评分

当短线和中线评分均可用时：

`综合评分 = 中线评分 × 60% + 短线评分 × 40%`

计算结果用于排序，不需要替换页面上已有的短线和中线评分展示。

缺失处理：

- 仅有中线评分时，使用中线评分。
- 仅有短线评分时，使用短线评分。
- 两项评分均缺失、分析失败或数据不足时，不生成有效综合评分并放到列表末尾。

## 排序规则

按以下优先级稳定排序：

1. 有有效综合评分的股票优先于无有效评分的股票。
2. 综合评分从高到低。
3. 综合评分相同时，建议状态按“买入、观望、回避”排列。
4. 仍然相同时，保留股票在当前自选股池中的原始顺序。

建议状态由现有短线和中线建议映射得到；只要存在明确回避且没有更积极的建议，不得排在同分的买入或观望股票之前。

## 数据流

1. 页面继续按现有逻辑加载自选股、实时行情、短线建议和中线建议。
2. 独立的纯排序函数接收原始股票顺序及两类建议状态。
3. 函数计算每只股票的综合评分、建议优先级和原始索引。
4. 页面渲染排序后的副本，不修改原始自选股数组。
5. 评分状态变化时重新计算排序结果。

## 异常与加载状态

- 建议仍在加载时，使用已经完成的评分；完全没有评分的数据暂时靠后。
- 单只股票分析失败不阻断整个列表排序。
- 排序函数不得修改输入数组，避免影响自选股保存和监控逻辑。

## 测试要求

- 双评分按 60%/40% 加权后高分股票在前。
- 只有一种评分时仍能参与排序。
- 无评分或数据不足股票位于末尾。
- 同分时按买入、观望、回避排序。
- 完全同分时保持原自选股顺序。
- 输入数组保持不变。
- WatchlistPage 渲染顺序随评分结果更新。

## 验收标准

- 用户打开自选股管理池后，高综合评分股票显示在上方。
- 低评分、回避和数据不足股票显示在下方。
- 刷新建议后列表自动更新顺序。
- 自选分组、保存顺序、持仓、回测和个股分析页面行为不受影响。
