# 策略评估与学习中枢设计规格

日期：2026-08-14

## 1. 目标

在现有“策略学习实验室”内部增加策略可信度与校准能力，不新增平行的大模块，不改变现有路由，也不新增 Supabase 表。第一阶段解决三个问题：

1. 用户能够区分“模型主观置信度”和“历史样本外表现”。
2. 用户能够看到策略在扣除费用后的收益、回撤、胜率和验证质量。
3. 数据或样本不足时，系统明确显示“证据不足”，不得把评分包装成胜率。

页面名称升级为“策略评估与学习中枢”，原有每日复盘、问题模式、候选策略和审批功能全部保留。

## 2. 范围

### 本次实现

- 从现有 `validationRuns`、`dailyReviews` 和 `decisionReviews` 读取数据。
- 增加纯计算模块，生成整体策略校准摘要。
- 在策略学习页面增加“策略表现与可信度校准”区域。
- 显示样本外验证次数、闭环交易数、费用后收益、胜率、最大回撤、置信度偏差、数据质量和泄漏检查结果。
- 无验证数据、交易样本不足或泄漏检查失败时给出明确降级状态。
- 保持本地 IndexedDB 数据结构不变，不增加云端存量。

### 后续阶段

- 将校准结果回传到自选股、个股分析、持仓、收件箱和做 T 页面。
- 按行业、市场状态、持有周期分别校准。
- 建立建议级 5/10/20 日结果追踪。

上述后续阶段依赖统一的建议标识和策略版本，不在本次为了赶进度而跨页面硬接。

## 3. 方案选择

采用“现有验证记录只读聚合”方案。

- 不重新执行大规模回测，页面加载快。
- 不修改正式策略和交易逻辑，风险较低。
- 不新增数据库表，避免增加云存储和迁移风险。
- 后续可以用相同计算接口接入分行业、分行情校准。

不采用页面内临时计算回测，也不直接把每日复盘置信度当成真实胜率。

## 4. 数据口径

只将 `walk_forward`、`out_of_sample` 和 `forward` 作为可信度校准证据；`stress` 只用于风险提示，不参与胜率平均。

聚合口径：

- 权重：每次验证的 `closedTrades`；没有闭环交易的验证不参与绩效加权。
- 胜率：`candidateMetrics.winRate`，统一按 0–100 百分比解释。
- 费用后收益：`candidateMetrics.netReturnPct`。
- 费用拖累：`grossReturnPct - netReturnPct`。
- 最大回撤：取有效验证中的最差值，而不是平均值。
- 置信度偏差：最近每日复盘平均置信度百分比减去样本外加权胜率。
- 泄漏检查：任一 `leakageChecks` 值为 `false`，整体状态即为阻断。
- 过拟合检查：任一 `overfittingChecks` 值为 `false`，整体状态至少降为谨慎。

证据等级：

- `insufficient`：没有有效样本外验证，或闭环交易少于 30 笔。
- `preliminary`：30–99 笔闭环交易。
- `established`：至少 100 笔闭环交易，且没有泄漏或过拟合失败。
- `blocked`：存在未来数据泄漏检查失败。

“模型置信度”始终单独展示，不得标注为胜率。

## 5. 页面设计

在顶部概览卡片之后、最新交易日复盘之前增加“策略表现与可信度校准”。

首行展示：

- 校准状态：证据不足 / 初步证据 / 已建立 / 验证阻断。
- 样本外验证次数。
- 闭环交易数。
- 数据截止时间。

指标区展示：

- 样本外胜率。
- 费用后收益。
- 最大回撤。
- 费用拖累。
- 模型置信度。
- 置信度偏差。

底部给出解释：

- 当前证据是否足以支持建议。
- 是否存在未来数据泄漏或过拟合风险。
- 样本不足时还差多少笔闭环交易。

## 6. 组件与边界

- `strategy-calibration-summary.ts`：无副作用的纯计算模块，负责数据筛选、加权和状态判定。
- `useStrategyLearningLab.ts`：额外读取 `validationRuns`，不改变复盘调度逻辑。
- `StrategyLearningLabPage.tsx`：只负责展示计算结果，不自行推导金融指标。

计算模块不依赖 React、Dexie、行情接口或 Supabase，便于单元测试与后续复用。

## 7. 错误与降级

- 无验证记录：显示“尚无样本外验证”，其他复盘功能正常可用。
- 指标包含非有限数值：忽略该验证的对应绩效，不使页面崩溃。
- 只有压力测试：显示风险测试存在，但不生成样本外胜率。
- 泄漏检查失败：用红色阻断提示，不展示“已建立可信度”。
- 数据读取失败：沿用页面现有错误区，不影响返回和导出按钮。

## 8. 测试要求

- 纯计算单元测试覆盖：无数据、加权计算、压力测试排除、样本门槛、泄漏阻断、异常数值。
- Hook 测试验证加载 `validationRuns`。
- 页面测试验证正常状态与证据不足状态的中文展示。
- 运行定向测试、TypeScript 类型检查、lint、完整测试和构建。

## 9. 非目标与安全边界

- 不修改买卖信号生成、实际持仓、虚拟持仓或 K 线数据源。
- 不自动批准策略，不自动改变正式策略权重。
- 不上传 Kronos 模型、缓存或实验服务。
- 不修改 Supabase schema、RPC 或云端已有数据。
